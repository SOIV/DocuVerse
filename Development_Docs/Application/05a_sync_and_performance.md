# DocuVerse 앱 저장·동기화·플랫폼·성능

로컬 우선 저장과 후속 온라인 서비스를 구분한다. 이 문서는 앱의 데이터 수명과 기기별 책임을 다루며, 사이트의 게시·실행 모드는 [프레임워크 문서](../Framework/README.md), 초기 구현 범위는 [앱 로드맵](05b_roadmap_and_future.md)을 따른다.

## 1. 로컬 저장과 외부 저장소

공통 문서·블록 모델을 저장·복원하고 버전·첨부 참조·미지원 확장 데이터를 보존한다. 실제 파일 선택·읽기·쓰기와 접근 권한은 플랫폼별 어댑터가 담당한다. 기본 문서 작성·로컬 저장에 공식 계정이나 클라우드를 필수로 요구하지 않는다.

Markdown·JSON 등 가져오기·내보내기 경로를 제공하되 필기·도형·고급 블록이 모든 형식에서 손실 없이 표현된다고 가정하지 않는다. 원본 보존용 데이터와 호환용 변환 결과를 구분하고 손실 가능 항목을 안내한다.

OneDrive·Google Drive·iCloud Drive·Dropbox 등 외부 저장소 연결은 플랫폼별 파일 제공자·권한·파일 조정 동작을 검증한 범위에서 제공한다. 데스크톱의 임의 동기화 폴더와 같은 방식이 모든 태블릿 환경에서 작동한다고 가정하지 않는다.

외부 서비스가 파일 동기화를 담당하는 구성은 자체 실시간 협업과 구분한다. 지연·충돌 파일·오프라인·접근 권한 해제·동시 저장을 확인하고, 단순 로컬·외부 저장은 문서 수량 제한을 두지 않는 방향을 유지한다.

## 2. 백업·이식성·마이그레이션

- 초기에는 로컬 문서 저장·재열기와 명시적인 가져오기·내보내기를 검증한다.
- 후속으로 정기·증분 백업, 버전 이력·복원 지점, 이력 비교와 자동 저장 간격을 검토한다.
- Notion·Obsidian 자료, HTML·Markdown·CSV·템플릿 등 가져오기는 형식별 지원 범위와 링크·미디어 보존 결과를 명시한다.
- 변환·최적화는 원본을 보존하고 손실·변형 항목을 안내한다. 지원하지 않는 서식·템플릿을 그대로 복원한다고 보장하지 않는다.
- 미디어 축소·중복 정리·압축은 원본 유지와 변경 적용 범위를 구분한다.

## 3. 자체 클라우드와 기기 동기화

공식 클라우드는 후속 선택형 서비스다. 변경 감지·전송, 오프라인 변경 보관·재연결, 충돌 처리, 선택적 동기화·백업을 검토한다. 구체적인 클라우드 사업자·전송·암호화·저장 구조는 기술·운영 검증 후 결정한다.

무료·유료 사용량과 공유 문서 수량 등은 [사업 모델 초안](04_business_model.md)에서만 관리한다. 앱·프레임워크 문서에서 제한 수치를 별도로 정의하지 않는다.

공통 데이터 모델을 사용해도 자동 동기화가 제공되는 것은 아니다. 우선 지원한 앱 환경 간 동기화를 검증하고, 정적 웹 사이트 게시와 실시간 양방향 편집 동기화는 구분한다. 협업의 권한·커서·댓글 등은 [공유·협업 문서](03_extensibility_and_collaboration.md)를 따른다.

기기별 설정·테마·단축키·작업 위치·플러그인 설정 동기화는 후속 후보다. 설정을 동기화하더라도 미검증 플러그인을 자동 활성화하거나 기기별 권한·비밀키를 무조건 복사하지 않는다.

## 4. 플랫폼 범위

| 환경 | 현재 방향 | 확인할 사항 |
| --- | --- | --- |
| iPadOS 태블릿 앱 | 우선 개발·검증 대상 | 터치·펜·키보드·IME, 로컬 저장·복원, 화면 회전·분할 화면 |
| Android 태블릿 앱 | 우선 개발·검증 대상 | 기기별 펜·입력 차이, 저장 권한, 화면·성능·복원 |
| 웹 문서 사이트 | 별도 셀프호스팅 프레임워크 | 정적 출력·브라우저 표시, 선택한 동적 구성 |
| 웹 편집·PWA | 추가 검증 후보 | 브라우저 저장·오프라인 범위, 입력·수명 관리 |
| iOS·Android 스마트폰 | 후속 검토 | 작은 화면·한 손 조작, 카메라·공유 시트·알림 |
| Windows·macOS 앱 | 제공 여부 미정 | 해당 앱 결정 이후 구현·지원 범위 검토 |
| Linux 앱·추가 CPU 환경 | 후속 검토 후보 | 수요·구현 방식·테스트 가능 범위 확인 |

계획상 대상과 지원 완료 태그는 구분한다. 웹 브라우저에서 작동했다는 이유로 해당 OS의 앱 태그를 부여하지 않는다. 구체적인 지원 기기·OS·브라우저 버전은 실제 테스트 결과로 정한다.

### 태블릿 우선 검증

문서 편집·필기·기본 블록·로컬 검색·저장을 우선 확인한다. 압력·기울기·펜/손가락 구분, 멀티태스킹·분할 화면은 구현한 기능과 기기 능력별로 검증한다. PDF 주석·고급 필기 인식·화이트보드 템플릿은 후속 후보로 분리한다.

### 추가 플랫폼의 후보 기능

스마트폰의 카메라·OCR·위치 노트·음성 입력·위젯, 웹 클리퍼·북마클릿·PWA, 데스크톱의 다중 모니터·창 배치·OS 탐색 통합·터미널 등은 해당 환경 제공 결정 이후 검토한다. 플랫폼별 전체 기능 일치를 전제로 하지 않는다.

## 5. 기기 전환과 호환 데이터

문서·블록의 원본을 공유하되 기능·UI·사용 권한·플러그인 실행은 각 기기의 검증 범위에 맞춘다. 미지원 블록은 대체 표시하고 원본을 유지한다. 자동 형식 변환이나 해상도 최적화를 원본 변경 없이 제공할 수 있는지 확인한다.

문서 위치·즐겨찾기·검색·레이아웃의 복원은 호환되는 상태만 적용하고 적용할 수 없는 설정은 안내한다. 플랫폼 호환 태그·영상·부분 지원 표시는 [공통 정책](../Framework/1.%20framework-runtime-and-plugin-policy.md)을 따른다.

## 6. 성능·리소스 검증

- 대규모 문서·미디어에서 입력 반응성, 점진적 로딩·가상화, 메모리 및 인덱싱 비용 확인
- 로컬 저장·백업 중 앱 중단·재시작·접근 권한 변경 시 복원 확인
- 동기화 기능 사용 시 불안정한 네트워크·재시도·대역폭·충돌 처리 확인
- 배터리·메모리·백그라운드 제한에 맞춰 사용하지 않는 작업 중단
- 미디어 압축·리사이징·중복 정리 시 원본 보존과 결과 확인

프레임워크의 동적 OFF에서는 동적 작업·통신을 시작하지 않는다는 별도 실행 정책을 따른다. 앱의 로컬 검색·필기·저장과 사이트 동적 기능을 같은 스위치로 묶지 않는다.

기기 선정·기록 항목은 [테스트 환경](../테스트%20기기.md)에 정리한다.
