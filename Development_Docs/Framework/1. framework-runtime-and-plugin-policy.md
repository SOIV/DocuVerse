# DocuVerse 프레임워크 실행 모드 및 플러그인 검증 정책

이 문서는 에디터 라이브러리, 태블릿 앱, 셀프호스팅 문서 프레임워크의 공통 방향과 실행 모드 및 마켓플레이스 심사 요구사항을 정의한다. 현재 단계의 설계이며, 아래 기능이나 검증 체계가 이미 구현되었다는 의미는 아니다.

프레임워크 자체의 목적과 제품 구성은 [제품 개요](00_overview.md), 모듈 경계는 [구조와 확장 설계](02_architecture_and_extensions.md), 단계별 범위는 [개발 로드맵](03_scope_and_roadmap.md)을 참고한다.

## 1. 적용 범위와 기준 문서

제품 관계·목적·확정 및 미결정 사항은 [제품 개요](00_overview.md), 공통 모듈·확장 경계는 [구조 문서](02_architecture_and_extensions.md), 라이선스와 전체 문서 기준은 [개발 문서 안내](../README.md)에서 관리한다.

이 문서는 셀프호스팅 사이트의 동적 실행 선택과, 앱·웹 확장의 플랫폼 호환·테스트 영상·마켓플레이스 공개 전 심사 기준을 담당한다. 공식·커뮤니티 여부나 기본 탑재 여부와 별개로 검증 기준을 적용한다.

## 2. 첫 구동 시 실행 모드 선택

셀프호스팅 프레임워크는 사이트를 처음 구성·구동할 때 운영자가 동적 기능을 켤지 끌지 명시적으로 선택하도록 한다. 방문자에게 매번 묻는 설정이 아니라 사이트 실행 구성이다.

- 선택 결과를 사이트 설정에 저장하고, 이후 구동에서 재사용한다.
- 선택 전에는 동적 기능을 자동으로 시작하지 않는다.
- 동적 기능을 켜면 해당 기능에 필요한 서버, 저장소, 인증 등 추가 구성을 안내한다. 선택만으로 모든 동적 기능이나 플러그인을 일괄 활성화하지 않는다.
- 설정에서 모드를 변경할 수 있도록 설계한다. 재빌드·재시작이 필요하다면 적용 전에 안내한다.
- 동적 기능은 서버 처리, 실시간 데이터 갱신, 외부 서비스 호출, 협업 등 실행 중 상태나 외부 연결을 사용하는 기능을 뜻한다. JavaScript 사용 자체를 금지한다는 뜻은 아니다.
- 태블릿 앱의 로컬 편집·저장·필기는 이 사이트 실행 모드와 구분한다. 동적 기능 OFF를 앱의 모든 로컬 기능 비활성화로 해석하지 않는다.

## 3. 동적 기능 OFF 시 동작

동적 기능을 끄면 정적으로 제공할 수 있는 기능과 정적 대체 기능만 사용할 수 있다. 정적 대체 기능이 없는 동적 기능은 모두 비활성화한다.

| 기능 유형 | OFF 모드 동작 |
| --- | --- |
| 미리 생성한 문서, 탐색 메뉴, 이미지·첨부 파일 | 정적 결과 제공 |
| 미리 생성한 검색 인덱스의 브라우저 검색, 로컬 필터 | 동적 서버 API·외부 서비스 호출 없이 동작할 수 있는 범위에서 제공 |
| 외부 데이터 기반 표·차트·위젯 | 정적 대체를 지원하면 빌드 시 생성하거나 명시적으로 내보낸 스냅샷 제공 |
| 로그인, 온라인 문서 편집·저장, 댓글 작성, 실시간 협업 | 비활성화 |
| 실시간 외부 API 호출, 웹훅, 예약 자동화, 서버 검색 | 비활성화 |

### 실행 및 데이터 처리 원칙

- UI만 비활성화하지 않는다. 해당 동적 기능의 실행 핸들러, 서버 경로, 백그라운드 작업, 구독 및 주기적 요청도 시작하지 않거나 중단한다.
- 정적 대체 경로와 동적 경로를 구분하여 정적 구성이 동적 서버나 서비스 의존성을 필수로 가져오지 않도록 한다.
- OFF 모드에서 외부 데이터를 가져와야 하는 정적 생성은 운영자가 별도로 실행하는 빌드·내보내기 단계에서만 허용한다. 방문자의 페이지 열기나 플러그인 로드로 동적 호출을 시작하지 않는다.
- 외부 데이터를 정적으로 공개할 때는 게시 가능한 데이터만 포함하고 인증 정보나 비밀키를 결과물에 포함하지 않는다.
- 스냅샷은 생성 시점과 갱신 방법을 표시하여 실시간 데이터와 구분한다. 동적 기능이 꺼져 있으면 자동 갱신하지 않는다.
- 정적 대체가 없는 기능은 사용 불가 이유를 표시한다. 지원하지 않는 블록의 원본 데이터를 삭제하거나 손상시키지 않는다.
- ON에서 OFF로 전환할 때 기존 데이터는 유지한다. 전환 도중 실행 중인 작업은 완료 또는 취소 상태를 확인한 후 모드 변경을 적용한다.
- 정적 대체 경로에도 해당 플랫폼·실행 모드에 대한 별도 동작 검증이 필요하다. 동적 모드에서의 성공으로 정적 모드 지원을 추정하지 않는다.

## 4. 플랫폼 호환 태그

플랫폼 호환 태그는 해당 플랫폼에서 정상 작동을 테스트하고, 그 근거를 마켓플레이스 심사에서 확인한 경우에만 부여한다. 제작자의 지원 선언만으로 검증 태그를 부여하지 않는다.

검증 기록에는 다음을 연결한다.

- 플러그인 이름과 제출 버전
- 플랫폼과 OS 버전, 기기 또는 실행 환경
- 호스트 앱·프레임워크 버전과 웹 환경의 브라우저·런타임 버전
- 테스트한 기능과 결과, 제한 사항
- 정적·동적 실행 모드 및 필요한 권한·서비스 설정
- 테스트 날짜와 해당 테스트 녹화 영상

플랫폼과 실행 모드는 독립적으로 표시한다. 예를 들어 웹에서 동적 기능을 확인했다는 사실만으로 정적 사이트 또는 태블릿 앱 지원 태그를 부여하지 않는다.

일부 기능만 작동하면 지원 범위를 명시하고 전체 지원으로 표시하지 않는다. 새 버전에 이전 버전의 검증 태그를 자동 승계하지 않으며, 변경 영향에 따른 재검증 근거를 심사한다. 과거 기록은 검증된 버전에 연결하여 보존한다.

## 5. 테스트 녹화 영상 제출

마켓플레이스 등록 시 지원을 주장하는 각 플랫폼에서 실제 테스트하며 녹화한 영상을 업로드해야 한다. 영상은 호환성의 근거이면서 기능 소개와 사용 방법을 확인할 수 있는 자료여야 한다.

영상에서 확인할 항목은 다음과 같다.

1. 테스트 플랫폼·실행 환경과 플러그인·호스트 버전
2. 기능의 목적과 사용 전 필요한 설정
3. 기능을 실행하는 실제 사용자 조작과 사용 순서
4. 조작에 따른 처리 결과와 정상 작동 여부
5. 제한 사항 및 지원 범위에 영향을 주는 조건
6. 정적 대체를 제공한다면 동적 기능 OFF 상태에서의 실제 사용 결과

플랫폼별 영상을 각각 제출하거나 하나의 영상 안에서 플랫폼별 구간을 명확히 구분할 수 있다. 소개 문구나 완성된 결과 화면만 있는 영상은 실제 동작 검증 영상으로 인정하지 않는다.

영상 제출만으로 호환성을 확정하지 않는다. 심사에서 제출 버전·환경·실행 결과를 대조하고, 필요한 경우 재현 확인이나 추가 자료를 요청할 수 있다. 공식 플러그인에도 같은 기준을 적용한다.

## 6. 영상 편집 허용 범위 및 등록 전 심사

테스트 영상의 편집은 허용한다. 다만 기능의 실제 동작이나 호환성을 오인하게 하거나 테스트 결과 확인을 방해하는 편집은 허용하지 않는다.

### 허용 가능한 편집

- 불필요한 대기 구간 제거 및 배속 처리. 처리 여부를 표시하고 실제 응답 속도를 오인시키지 않아야 한다.
- 설명 자막, 음성 설명, 화면 확대 및 강조
- 개인정보, 계정 정보, API 키 등 민감한 정보 가림
- 기능과 플랫폼별 구간 분리. 필요한 사용 순서와 결과를 확인할 수 있어야 한다.

### 거부 사유가 될 수 있는 편집

- 실패, 오류, 비정상 종료 또는 결과 불일치를 숨겨 정상 작동한 것처럼 보이게 하는 편집
- 다른 플랫폼·버전·실행 모드의 결과를 이어 붙여 해당 환경에서 작동한 것처럼 보이게 하는 편집
- 핵심 조작이나 결과를 잘라내거나 과도하게 가려 실제 동작 확인이 불가능한 영상
- 결과 화면 합성이나 조작으로 구현되지 않은 기능을 동작한 것처럼 표현하는 편집
- 필수 준비 단계, 수동 개입 또는 외부 의존성을 숨겨 사용 방법이나 동작 범위를 오인하게 하는 편집

마켓플레이스 공개 이전의 확인·심사 단계에서 영상을 검토한다. 문제가 되는 편집이 확인되면 등록을 거부할 수 있으며, 확인이 어려운 경우 필요한 구간의 편집 전 영상 또는 재녹화 자료를 요청할 수 있다. 반려 사유와 보완할 항목을 제작자에게 안내한다.

### 제출 화면에 표시할 안내 문구

> 테스트 영상은 편집하여 제출할 수 있습니다. 다만 실제 동작, 사용 절차 또는 플랫폼 호환성을 오인하게 하거나 정상 작동 여부를 확인하기 어렵게 하는 편집은 허용되지 않습니다. 이러한 편집이 확인되면 마켓플레이스 공개 전 심사에서 등록이 거부될 수 있으며, 추가 자료나 재촬영을 요청할 수 있습니다.

## 7. 구현 시 확인할 항목

- 첫 구동에서 명시적으로 모드를 선택하고 다음 구동에서도 선택이 유지되는가?
- OFF 상태에서 정적 기능·대체 기능만 작동하며 동적 서버 경로와 백그라운드 요청이 실행되지 않는가?
- 정적 대체가 없는 플러그인은 실행되지 않으면서 문서 원본은 보존되는가?
- ON/OFF 전환에서 실행 중 작업과 저장 데이터가 올바르게 처리되는가?
- 플랫폼·버전·실행 모드별 검증 기록과 영상이 연결되어 있으며 미검증 범위에 태그가 붙지 않는가?
- 공개 전 영상 심사 및 거부·보완 요청 절차가 적용되는가?
