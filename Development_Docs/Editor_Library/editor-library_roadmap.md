# DocuVerse 에디터 라이브러리 개발 로드맵

기능 요구사항은 [에디터 기술 문서](1.%20editor-library-document.md), 패키지·설치 책임은 [코어·어댑터 전략](2.%20core-adapter-package-strategy.md)을 따른다. 이 문서는 구현 순서와 검증 기준에 집중한다.

제품 간 우선순위·선행 조건·배포 판단은 [통합 로드맵](../ROADMAP.md)을 따른다. 아래 번호는 에디터의 작업 묶음이며 각 묶음 전체를 끝내야 다음 제품을 시작하거나 첫 배포를 할 수 있다는 뜻은 아니다. 실제 필요한 최소 범위부터 앱·웹과 연결한다.

## 1. 개발 원칙

- 에디터를 독립 라이브러리로 제공하며 앱·프레임워크 전체를 필수 의존성으로 두지 않는다.
- 공통 문서·변경 로직, 플랫폼별 입력·표시, 선택형 파서·고급 기능을 분리한다.
- iPadOS·Android 태블릿 편집과 웹 읽기 전용 표시를 초기에 검증한다. 에디터의 모든 후보 기능을 완성한 뒤 앱·웹을 시작하는 순서로 고정하지 않는다.
- 구체적인 편집 엔진, UI 기술, 번들러·테스트 도구와 정식 패키지 이름은 검증 후 확정한다. 기존 TypeScript·ProseMirror·Rollup·Jest 구상은 후보로 유지한다.
- 에디터 MIT 배포는 기존 기획 목표이며 현재 라이선스 상태는 [공통 문서](../README.md)를 따른다.

기존 문서의 단계별 주 단위 일정과 총 4~5개월 추정은 근거가 재검증되지 않아 현행 계획에서 제외한다. 인력·기술·지원 범위가 확정된 뒤 기간을 산정한다.

## 2. 제품별 작업 묶음과 완료 기준

| 묶음 | 결과물 | 완료 기준 |
| --- | --- | --- |
| 1. 공통 모델·최소 코어 | 문서·블록 스키마, 변경·선택·history, 버전·확장 데이터 규약 | 대표 문서 생성·변경·저장·재열기에서 데이터 보존 |
| 2. 실제 환경 연결 | 최소 편집 어댑터와 읽기 전용 웹 렌더러 | iPadOS·Android 편집 환경 및 웹 표시에서 같은 문서를 검증, UI 기술 선택 근거 확보 |
| 3. 기본 편집·변환 | 기본 서식·블록·표, Markdown·허용 HTML 가져오기·내보내기 | 선언한 변환 범위의 왕복 확인, 미지원 정보의 보존·손실 안내 |
| 4. 확장 인터페이스 | 스키마·명령·표시 등록, 선택형 모듈·플랫폼 진입점 | 예제 확장을 공개 인터페이스로 구성하고 미지원 환경에서 데이터 보존 |
| 5. 고급 문법·표 | 나무위키 스타일 파서, 고급 표·수식 등 선택형 기능 | 기능별 지원 범위·오류 처리·읽기 전용 표시 확인 |
| 6. 협업 연결 검토 | 선택형 협업 데이터 규약과 호스트 연결 예제 | 로컬 편집의 독립성, 권한·통신 경계, 재연결 동작 확인 |
| 7. 배포 준비 | 타입·문서·설치 도구, 검증 환경 목록, 예제·테스트 영상 | 지원 플랫폼·버전·기능별 근거와 재현 절차 확보 |

기본 입력·데이터 보존·보안·성능 검증은 개발 전반에서 수행한다. 마지막 배포 준비 묶음까지 검증이나 SDK 설계를 미루지 않는다. 웹 사이트 초기 정적 기능은 묶음 2~4의 필요한 결과를 이용해 별도로 진행할 수 있다.

## 3. 실제 환경 검증

### 태블릿 편집

- 키보드·한국어 IME·터치 선택·클립보드·화면 회전·분할 화면
- 필기 블록을 포함한다면 펜 입력·색상·압력 등 구현한 기능과 저장 후 복원
- 기기별 반응성·메모리와 미지원 기능의 대체 동작

### 웹 표시·선택형 편집

- 편집 UI 없는 문서 렌더링 및 정적 출력
- 동적 서버·특정 UI 어댑터 없이 파서·읽기 전용 렌더러 사용
- 웹 편집을 제공할 경우 해당 브라우저의 입력·선택·IME 별도 검증

### 확장과 변환

- 지원하지 않는 블록·플러그인 부재·스키마 버전 차이에서 원본 보존
- Markdown·HTML·나무위키 스타일 문법별 지원 범위와 변환 손실
- 정적 대체가 있는 블록과 없는 블록의 표시·실행 차이

호환 태그·영상 제출은 [공통 정책](../Framework/1.%20framework-runtime-and-plugin-policy.md), 기기 선정과 기록 항목은 [테스트 환경 문서](../테스트%20기기.md)를 따른다.

## 4. 제품 간 연결

- 앱은 파일·계정·워크스페이스·동기화를, 에디터는 문서 편집 규칙을 담당한다.
- 프레임워크는 문서 게시·탐색·정적 빌드·선택형 동적 서버를 담당한다.
- 편집 UI와 읽기 전용 렌더러는 서로 독립적으로 사용할 수 있도록 경계를 검증한다.
- 추가 React·Vue·Svelte·WebView·네이티브 어댑터는 실제 수요와 검증 결과에 따라 제공한다. 데스크톱 패키지 후보가 공식 데스크톱 앱 출시를 확정하지 않는다.

앱·프레임워크의 후속 일정은 각각 [앱 로드맵](../Application/05b_roadmap_and_future.md)과 [프레임워크 로드맵](../Framework/03_scope_and_roadmap.md)에서 관리한다.
