# DocuVerse 프레임워크 구조와 확장 설계

이 문서는 논리적인 모듈 경계를 제안한다. 모듈 이름은 책임을 설명하기 위한 것이며, 정식 패키지 이름이나 공개 API가 확정되었다는 의미는 아니다.

## 1. 계층과 의존성

| 계층 | 책임 | 의존성 경계 |
| --- | --- | --- |
| 공통 문서·에디터 기반 | 문서 모델, 변경 명령, 파서, 직렬화, 스키마 버전 | 앱 UI·사이트 라우팅·서버 구현에 의존하지 않음 |
| 읽기 전용 렌더러 | 문서를 웹 페이지와 블록으로 표시 | 에디터 입력·편집 UI 없이 사용 가능 |
| 사이트 구성 | 문서 경로, 탐색, 메타데이터, 테마, 빌드 | 공통 문서 처리·렌더러를 조합 |
| 브라우저 기능 | 미리 생성한 인덱스 검색, 필터, 로컬 상호작용 | 서버·외부 서비스가 필요한 동작을 명시적으로 구분 |
| 동적 서버 | 인증 연결, 문서 조회·변경, 권한, 이벤트 처리 | 선택한 저장소·인증 구현을 연결 |
| 확장 SDK·호스트 | 명령·이벤트·기능 등록, 권한·모드 확인, 실행 수명 관리 | 호스트가 제공하는 기능 범위 안에서 확장 실행 |
| 플랫폼 어댑터 | UI 표시·입력, 저장소, 네트워크·인증 연결 | 앱·브라우저·서버의 환경 차이 처리 |
| 생성·빌드 도구 | 사이트 초기 구성, 실행 모드 설정, 빌드·배포 결과 생성 | 선택한 구성에 필요한 모듈만 사용 |

문서 모델과 변경 규칙은 [기존 에디터 코어·어댑터 전략](../Editor_Library/2.%20core-adapter-package-strategy.md)을 기반으로 공유한다. 프레임워크가 별도의 호환되지 않는 문서 편집 모델을 만들지 않도록 한다.

정적 사이트에서 읽기 전용 렌더러를 쓸 때 편집 UI, 동적 서버, 특정 외부 서비스 SDK가 필수 의존성으로 따라오지 않도록 진입점과 의존성을 분리한다. 읽기 전용 배포 결과에서는 편집 화면을 제외할 수 있어야 한다.

## 2. 문서와 게시 데이터

- 문서 ID, 문서·블록 스키마 버전, 첨부 파일 참조 및 확장 데이터를 앱과 웹이 해석할 수 있는 공통 규약으로 정의한다.
- Markdown 등 텍스트 형식과의 가져오기·내보내기에서 표현 가능한 범위와 손실되는 정보를 명시한다. 필기·고급 블록까지 텍스트 형식으로 완전히 보존된다고 가정하지 않는다.
- 태블릿 앱의 로컬 저장소와 프레임워크의 콘텐츠 소스는 각 환경의 어댑터가 담당한다.
- 앱 문서의 사이트 게시는 사용자가 선택한 가져오기·내보내기 또는 별도 연결 절차로 수행한다. 공통 데이터 모델이 자동 동기화를 의미하지 않는다.
- 지원하지 않는 블록은 원본 데이터와 버전을 유지하면서 대체 표시한다. 읽기·저장 과정에서 알 수 없는 확장 데이터를 제거하지 않는다.
- 공개 사이트용 결과물에는 게시 대상으로 선택한 문서와 첨부 자료만 포함한다. 앱의 전체 작업공간이나 계정 설정을 자동 게시하지 않는다.

## 3. 정적 게시 경로

```text
문서·첨부 자료 + 사이트 설정
  → 문서 파싱·검증
  → 게시 대상·내부 링크·탐색 구조 구성
  → 정적 블록 렌더링 및 선택한 스냅샷 생성
  → HTML·정적 자산·선택형 검색 인덱스
  → 운영자가 선택한 정적 호스팅에 배포
```

정적 페이지 생성과 브라우저 내 상호작용은 구분한다. 미리 생성한 인덱스를 읽는 검색, 이미 내려받은 데이터의 정렬·필터 등은 동적 서버 없이 제공할 수 있다.

외부 데이터 스냅샷을 만들려면 운영자가 빌드·내보내기 작업을 명시적으로 실행해야 한다. OFF 모드에서는 사이트 방문이나 플러그인 초기화가 실시간 외부 호출을 유발하지 않는다. 정적 대체 결과에는 생성 시점과 갱신 방법을 표시한다.

## 4. 동적 기능 경로

```text
사이트 첫 구성 → 동적 기능 ON/OFF 저장
  ├─ OFF → 정적 게시·브라우저 로컬 기능·정적 대체만 제공
  └─ ON  → 선택한 기능의 서버·저장소·인증 설정 확인
           → 요청 권한 확인 → 기능 실행 → 변경 저장·이벤트 처리
```

동적 기능 ON은 사용 가능한 실행 경로를 여는 설정이다. 인증, 협업, 외부 커넥터 등을 모두 자동 시작하지 않으며 기능별 활성화·설정을 별도로 관리한다.

모드 변경 시 호스트는 기능의 시작·중단을 관리한다. OFF에서는 서버 핸들러, 타이머, 구독, 외부 호출 등 해당 기능의 실행 경로를 비활성화해야 한다. 지원하지 않는 구성을 발견하면 이유를 안내하고 실행을 막으며, 저장된 문서나 플러그인 데이터는 유지한다.

자세한 동작과 심사 기준은 [실행 모드 및 검증 정책](1.%20framework-runtime-and-plugin-policy.md)을 따른다.

## 5. 확장 지점과 책임

| 확장 종류 | 등록하는 기능 | 재사용 방향 |
| --- | --- | --- |
| 문서 확장 | 블록·문법·변환·계산 | 문서 데이터와 순수 로직 공유 |
| 표시 확장 | 블록 렌더러, 정적 대체 표시, UI | 데이터는 공유하고 플랫폼별 표시 구현 |
| 사이트 확장 | 탐색, 테마, 빌드 처리 | 웹 프레임워크 중심 |
| 서비스 커넥터 | 외부 API 조회·작업, 데이터 변환 | 서비스 로직은 공유 가능, 인증·실행 위치는 별도 |
| 앱 확장 | 펜 입력, 로컬 파일 처리, 네이티브 UI | 해당 앱 환경 중심 |

에디터 확장은 문서 편집에 필요한 스키마·명령·표시를 담당하고, 호스트 확장은 사이트·앱의 메뉴, 저장소, 서비스 연결 등을 담당한다. 같은 배포물에 둘을 포함할 수 있지만 등록 경로와 실행 책임은 구분한다.

공식 플러그인도 공개 SDK를 통해 기능을 구현한다. 공통 인증 연결, 요청 취소·재시도, 비밀키 보관 등은 호스트의 재사용 가능한 서비스로 설계하고, 특정 서비스의 API 매핑은 커넥터가 담당한다. 서버 비밀키를 브라우저 번들에 포함하지 않는다.

## 6. 플랫폼 및 모드 호환 정보

플러그인 메타데이터에는 다음 정보를 표현할 수 있어야 한다. 실제 필드 이름과 파일 형식은 SDK 설계에서 정한다.

| 정보 | 의미 |
| --- | --- |
| 식별자·버전 | 어떤 플러그인 배포물을 실행·검증하는지 식별 |
| 호스트·문서 규약 버전 | 필요한 API와 문서 스키마의 호환 범위 |
| 대상 환경 | 웹 브라우저, 웹 서버, iPadOS 앱, Android 앱 등 제작자가 지원하려는 환경 |
| 필요 기능·권한 | 네트워크, 저장소, 파일 접근, 인증 등 실행 조건 |
| 실행 모드 | 정적·브라우저 로컬·동적 서버에서 제공하는 기능 |
| 정적 대체 | 대체 표시·스냅샷 생성의 지원 여부와 갱신 방법 |
| 검증 기록 참조 | 실제 테스트한 버전·환경·기능과 심사한 영상 연결 |

제작자가 작성한 대상 환경과 마켓플레이스가 심사한 호환 태그는 구분한다. 호스트는 현재 플랫폼·모드·권한이 맞는 기능만 활성화한다. 메타데이터 선언만으로 접근을 허용하지 않으며 실행 경계에서 권한과 모드를 확인한다. 커뮤니티 코드의 격리·샌드박스 구현은 별도 기술 검증 대상이다.

전체 패키지를 모든 환경에서 실행시키기보다 순수 로직과 플랫폼별 진입점을 분리한다. 웹용 UI를 포함한 패키지라도 앱에서 검증된 공통 기능만 사용할 수 있도록 구성할 수 있다.

## 7. 공개 API와 외부 서비스 연결

외부 도구가 DocuVerse를 조작하는 API와 DocuVerse가 외부 서비스를 호출하는 커넥터를 별도 확장 지점으로 둔다.

- 공개 API 후보: 문서 조회·검색·작성, 첨부 자료 처리, 변경 이벤트 구독.
- 외부 커넥터 후보: 캘린더·Git·지도·AI 등 서비스 데이터 조회와 작업.
- 정적 구성은 게시 결과를 제공하고, 문서 변경 API·웹훅·실시간 구독은 동적 구성에서 제공한다.
- 서비스별 인증·권한·요청 제한을 처리하는 경로는 호스트 환경에 맞춰 연결한다.
- 정확한 엔드포인트, 프로토콜 및 OpenAPI 명세 기반 자동화는 추후 확정한다.

## 8. 검증 기준

- 하나의 대표 문서를 앱 편집과 웹 렌더링에서 사용하여 공통 모델의 유효성을 확인한다.
- 정적 배포를 동적 서버 없이 구동하고, OFF 상태에서 동적 API·외부 서비스 요청이나 백그라운드 작업이 발생하지 않는지 확인한다.
- 한 확장을 통해 공통 계산·문서 데이터 재사용과 플랫폼별 UI 분리를 확인한다.
- 플러그인 부재·지원하지 않는 블록·버전 차이가 있어도 원본 데이터가 보존되는지 확인한다.
- 플랫폼별 테스트·녹화·공개 전 심사를 통과한 버전과 기능 범위에만 호환 태그를 부여한다.
