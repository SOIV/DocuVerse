# DocuVerse 프레임워크 개발 범위와 로드맵

공통 에디터를 기반으로 실제 태블릿 편집과 웹 게시를 함께 검증하면서 프레임워크를 구체화한다. 에디터의 모든 후보 기능을 완성해야만 웹 검증을 시작할 수 있는 순서로 고정하지 않는다.

이 문서는 단계별 결과와 완료 기준을 정의한다. 인력, 기술 검증 및 범위가 확정되기 전에는 출시 날짜나 개발 기간을 산정하지 않는다.

제품 간 우선순위·선행 조건·배포 판단은 [통합 로드맵](../ROADMAP.md)을 따른다. 아래 번호는 프레임워크의 작업 묶음이며 정적 사이트는 필요한 공통 기반·모드 검증·배포 준비를 마치면 동적 기능·커넥터·마켓플레이스보다 먼저 배포할 수 있다. 공식 앱의 전체 완성을 기다릴 필요도 없다.

## 1. 최소 구현 범위

첫 프레임워크 결과물은 문서를 가져와 탐색·조회·검색할 수 있는 셀프호스팅 사이트다. 초기에는 정적 경로를 먼저 완성하고 동적 기능을 선택적으로 추가할 수 있는 경계를 검증한다.

- 공통 문서 모델을 읽는 문서 처리·읽기 전용 렌더러
- 최소 문서 경로, 문서 트리·탐색, 내부 링크 및 기본 테마
- HTML·첨부 자산의 정적 출력과 선택형 사전 생성 검색 인덱스
- 첫 구동 동적 기능 ON/OFF 선택, 설정 저장 및 기능 실행 제어
- 기존 웹 프로젝트에서 렌더러를 단독 사용하는 예제
- 플러그인 등록·해제, 필요한 환경·권한 선언 및 정적 대체 경로의 최소 규약
- 앱·웹에서 하나의 문서와 한 확장 기능을 검증하는 예제
- 설치·설정·정적 배포·지원 범위에 대한 개발자 문서

## 2. 제품별 작업 묶음과 완료 기준

| 묶음 | 결과물 | 완료 판단 기준 |
| --- | --- | --- |
| 1. 공통 문서 경계 검증 | 최소 에디터, 대표 문서, 읽기 전용 웹 렌더러 | 동일 문서가 태블릿 편집 환경과 웹에서 해석되며 지원 범위·데이터 보존 확인 |
| 2. 정적 사이트 구성 | 사이트 초기 구성, 탐색·테마·검색, 정적 빌드·배포 예제 | 동적 서버 없이 사용 가능하고 에디터·서버 전체 없이 렌더러 단독 통합 가능 |
| 3. 모드와 확장 검증 | 첫 구동 선택·저장, 플러그인 실행 제어, 정적 대체 예제 | OFF에서 동적 처리가 실행되지 않고 정적 대체 또는 비활성화가 적용됨 |
| 4. 최소 동적 기능 | 대표 동적 기능 한 개와 필요한 저장소·권한 연결 | ON에서 기능 사용, OFF에서 중단, 재시작·모드 변경 시 데이터 보존 확인 |
| 5. 공식 API 커넥터 검증 | 외부 서비스 커넥터 한 개와 설정·사용 예제 | 필요한 환경별 실제 동작, 실패 처리, 지원 시 정적 스냅샷 경로 확인 |
| 6. 배포·마켓플레이스 준비 | SDK·템플릿, 버전 관리, 영상 업로드·심사·호환 태그 | 제출 버전과 검증 환경·영상 연결, 공개 전 심사·반려 처리 가능 |

대표 문서의 블록 종류, 첫 동적 기능 및 외부 서비스는 구현 착수 시 선택한다. 정적 대체를 검증하는 기능과 대체할 수 없는 기능을 모두 포함하여 실행 제어를 확인한다.

마켓플레이스 공개 전이라도 공식 예제부터 플랫폼별 테스트와 녹화 기록을 남긴다. 검증되지 않은 플랫폼에 호환 태그를 부여하지 않는다.

## 3. 태블릿 앱과의 개발 연결

- iPadOS·Android 태블릿에서 입력, 선택, 저장, 문서 재열기를 검증해 공통 문서 모델과 어댑터의 경계를 확인한다.
- 웹 프레임워크와 앱은 공통 기반을 공유하지만 서로의 모든 기능 구현이 완료될 때까지 출시가 종속되지는 않도록 범위를 관리한다.
- 앱에서 만든 문서를 명시적인 내보내기·가져오기로 게시하는 경로를 먼저 검증할 수 있다. 자동 동기화와 실시간 협업은 별도 후속 기능으로 다룬다.
- 웹 전용 빌드 플러그인이나 앱 전용 입력 확장은 상대 환경에서 실행할 필요가 없다. 공통 블록 데이터와 표시·계산 기능부터 공유 범위를 검증한다.

## 4. 후속 확장 후보

- 문서 작성·검색 공개 API, 이벤트 구독 및 외부 자동화
- 계정·권한·온라인 편집, 댓글, 공유 및 실시간 협업
- 여러 콘텐츠 소스와 저장소·인증 어댑터
- 추가 공식 커넥터, 고급 블록, 테마 및 사이트 템플릿
- OpenAPI 명세를 이용한 연결 설정·도구 생성
- 문서 스키마·플러그인 버전 마이그레이션 도구
- 추가 웹 기술 어댑터와 운영 도구

후속 후보가 기본 탑재나 초기 지원을 의미하지는 않는다. 공식 관리 여부, 기본 제공 여부, 플랫폼별 지원과 정적 대체 여부를 기능별로 결정한다.

## 5. 초기 범위에서 보류할 항목

- 모든 외부 서비스와 모든 플랫폼에 대한 일괄 호환
- 모든 동적 기능의 자동 정적 변환
- 여러 웹 프레임워크·호스팅·저장소의 동시 초기 지원
- 모든 앱 기능을 웹 사이트에 그대로 제공하는 구성
- Windows·macOS 앱의 확정 구현과 출시 일정
- 전체 IDE, 대규모 기업 관리, 결제·구독 등 기존 앱 비전의 모든 확장 기능

## 6. 착수 전 결정할 사항

최초 구현의 웹 기술, 태블릿 렌더링·입력 방식, 대표 문서 형식, 첫 동적 기능, 첫 커넥터 및 플러그인 격리 방식을 기술 검증으로 좁힌다. 패키지·라이선스·배포 정책과 마켓플레이스 운영 방식도 출시 전에 확정해야 한다.

실행 모드·영상 심사 기준은 [정책 문서](1.%20framework-runtime-and-plugin-policy.md), 모듈 경계는 [구조 문서](02_architecture_and_extensions.md)를 따른다.
