# DocuVerse 프레임워크 제품 개요와 범위

## 1. 제품 정의

DocuVerse 프레임워크는 개발자가 문서 사이트, 위키, 지식 포털을 구성하고 자신의 환경에 배포할 수 있는 셀프호스팅 프레임워크이자 재사용 라이브러리 모음이다.

문서 게시에 필요한 기본 구성을 제공하면서, 동적 기능과 플러그인은 운영자가 필요한 만큼 선택하도록 한다. 정적 사이트만 운영하는 경우에는 실행 중인 DocuVerse 전용 애플리케이션 서버를 필수로 요구하지 않는다.

## 2. 프로젝트의 세 가지 결과물

| 결과물 | 주 사용자와 역할 | 독립 사용 |
| --- | --- | --- |
| 에디터 라이브러리 | 개발자가 자신의 제품에 문서 작성·편집 기능을 통합 | 에디터만 사용 가능 |
| 공식 태블릿 앱 | 사용자가 텍스트·블록·필기를 작성하고 로컬에서 관리 | 사이트 운영 없이 사용 가능 |
| 셀프호스팅 프레임워크·라이브러리 | 운영자가 문서 사이트·위키를 구성하고 배포 | 공식 앱 없이 사이트 구축 가능 |

공식 앱은 iPadOS와 Android 태블릿을 우선 대상으로 한다. Windows와 macOS 앱 제공 여부는 추후 결정한다. 웹 프레임워크를 제공한다는 사실이 별도의 데스크톱 앱 출시를 의미하지 않는다.

공통 에디터와 문서 모델은 두 제품의 기반이다. 에디터만 사용하는 개발자에게 사이트 프레임워크 전체를 요구하거나, 사이트를 운영하는 사용자에게 태블릿 앱을 요구하지 않는다.

```text
공통 문서 모델 · 파서 · 직렬화 · 에디터 로직
│
├─ 플랫폼 입력·표시 어댑터 → 공식 태블릿 앱
│
└─ 웹 문서 렌더러 → 셀프호스팅 프레임워크
                    ├─ 정적 사이트 출력
                    ├─ 선택형 브라우저 기능
                    └─ 선택형 동적 서버·서비스

플러그인: 공통 로직 + 실제 지원하는 환경의 구현
```

## 3. 제공하는 사용 방식

### 준비된 사이트 구성 사용

프로젝트 생성 도구, 기본 테마, 문서 탐색, 렌더링 및 빌드 구성을 조합해 문서 사이트를 시작한다. 운영자는 콘텐츠와 사이트 설정을 관리하고 결과물을 자신의 호스팅 환경에 배포한다.

### 기존 프로젝트에 라이브러리 통합

문서 파서, 렌더러, 탐색 UI 등 필요한 구성 요소만 기존 웹 프로젝트에 연결한다. 에디터를 포함할지는 해당 프로젝트가 편집 기능을 제공하는지에 따라 선택한다.

### 선택적 동적 기능 사용

로그인, 온라인 문서 편집·저장, 댓글, 외부 API 연동 등 필요한 동적 기능을 추가한다. 각 기능에 필요한 저장소·인증·서버 구성을 함께 설정하며, 전체 동적 기능이 일괄 활성화되지는 않는다.

## 4. 정적·동적 기능의 선택

사이트 첫 구성·구동 시 운영자가 동적 기능 ON/OFF를 선택하고 설정을 저장한다.

- OFF: 정적 출력, 미리 생성한 검색 인덱스, 정적 대체를 지원하는 블록을 제공한다. 정적 대체가 없는 동적 기능은 실행 경로와 백그라운드 작업까지 비활성화한다.
- ON: 정적 기능을 유지하면서 설정한 동적 기능을 사용할 수 있다.
- 서버 API를 호출하지 않는 브라우저 내 검색·필터·차트 조작 등은 OFF에서도 제공할 수 있다. 모든 JavaScript 실행을 동적 서버 기능과 동일하게 취급하지 않는다.
- 정적 대체는 기능마다 별도로 구현·검증한다. 모든 동적 기능을 정적으로 변환할 수 있다고 가정하지 않는다.

첫 구동은 운영자의 사이트 설정 단계이며, 사이트 방문자마다 모드를 선택하는 방식은 아니다. 모드 전환과 스냅샷의 세부 동작은 [실행 모드 정책](1.%20framework-runtime-and-plugin-policy.md)을 따른다.

## 5. 공식 기능과 생태계

문서 모델, 확장 인터페이스 및 공통 실행 규칙은 기반 계층에서 제공한다. 사이트 탐색·기본 테마 등은 기본 구성을 이루고, 외부 서비스 연동이나 고급 블록은 별도 공식 플러그인으로 제공할 수 있다.

공식 관리 여부, 기본 탑재 여부, 지원 플랫폼 및 정적·동적 지원 여부는 각각 구분한다. 기본 탑재된 기능도 내부적으로는 교체 가능한 모듈이나 플러그인으로 구성할 수 있다.

공식·커뮤니티 플러그인은 공통 공개 SDK를 사용한다. 프레임워크에서 만든 플러그인의 일부 로직이나 기능은 앱에서도 사용할 수 있도록 설계하되, 각 환경의 정상 작동 검증을 통과한 범위만 호환으로 표시한다.

## 6. API 관련 방향

- 외부에서 DocuVerse 문서를 조회·작성하거나 이벤트를 받는 공개 API와, DocuVerse가 외부 서비스를 호출하는 커넥터를 구분한다.
- 정적 결과물만 배포하는 구성에서는 문서 작성 API나 서버 이벤트 처리를 실행하지 않는다.
- 외부 서비스별 연동은 공식 또는 커뮤니티 플러그인으로 확장한다. 공통 인증·요청 처리와 서비스별 동작은 분리한다.
- 이번 구상에서 말하는 오픈 API 연동은 외부 서비스와 공개 API 활용을 포함한다. OpenAPI 명세 가져오기·자동 연동 생성은 검토 후보이며 필수 초기 기능으로 확정하지 않는다.

## 7. 결정된 방향과 남은 결정

결정된 방향은 에디터·앱·프레임워크 분리, 태블릿 앱 우선, 셀프호스팅과 개별 라이브러리 사용, 첫 구동 동적 기능 선택, 일부 플러그인 호환, 플랫폼별 테스트·영상 심사다.

다음 항목은 구현 검증 후 결정한다.

- 프레임워크의 기반 웹 기술과 초기 지원 어댑터
- 태블릿 앱의 네이티브·WebView 등 구현 방식
- 정식 패키지 이름, 저장소 구성, 공개 API와 문서 저장 스키마
- 첫 공식 외부 API 커넥터와 기본 탑재 플러그인 목록
- 동적 서버의 배포 방식, 인증·저장소의 초기 지원 구현
- 프레임워크·관련 패키지의 라이선스와 배포 정책
- 마켓플레이스 운영 인력, 영상 저장·제공 방식 및 구체적인 심사 도구
- Windows·macOS 앱 제공 여부 및 개발 일정

기존 앱 문서의 기능 아이디어 전체를 프레임워크 초기 범위로 가져오지 않는다. 단계별 범위는 [개발 로드맵](03_scope_and_roadmap.md)을 기준으로 구체화한다.
