# DocuVerse 에디터 라이브러리 기술 문서

현재는 기능·설계 요구사항 단계다. 패키지 구조는 [코어·어댑터 전략](2.%20core-adapter-package-strategy.md), 구현 순서는 [에디터 로드맵](editor-library_roadmap.md)을 따른다. 제품 구성과 라이선스 상태는 [공통 문서](../README.md)에 정리한다.

## 1. 목적과 책임

독립 에디터 라이브러리는 공통 문서 모델, 문서 변경 명령, 선택·실행 취소/다시 실행, 파싱·직렬화 및 에디터 확장 인터페이스를 제공한다. 태블릿 앱의 입력·편집과 프레임워크의 웹 표시에서 같은 문서를 해석할 수 있도록 설계한다.

| 영역 | 담당 계층 |
| --- | --- |
| 문서·블록 스키마, 변경·계산·변환 규칙 | 공통 코어 및 선택형 문서 확장 |
| 입력·선택 표시, 터치·펜, 클립보드, 편집 툴바 | 플랫폼별 편집 어댑터·UI |
| 웹 읽기 전용 표시·정적 출력 | 별도 렌더러와 사이트 빌드 계층 |
| 파일 저장·워크스페이스 검색·문서 트리 | 앱·프레임워크 호스트 및 저장소 어댑터 |
| 계정·권한·공유·통신·동기화 서버 | 선택형 호스트 서비스·플러그인 |

코어의 규약을 공유하되 전체 기능을 필수 번들에 넣지 않는다. 포맷 파서, 고급 표·수식, 협업 데이터 연결은 필요한 프로젝트만 선택할 수 있도록 모듈화한다. 편집 가능한 앱이 정적 사이트의 실행 모드에 종속되지는 않는다.

## 2. 기본 문서와 편집

- 문단, 제목, 목록, 링크, 인용, 코드 블록 등 최소 블록과 기본 텍스트 서식
- 굵게·기울임·밑줄·취소선 및 지원하는 범위의 색상·단락 속성
- 이미지·첨부 파일의 참조와 대체 표시. 실제 업로드·보관은 호스트에서 처리
- 선택 상태, 편집 명령, 변경 이벤트, 실행 취소/다시 실행
- WYSIWYG·소스 표시 연결. 변환 가능한 서식과 소스 보존 범위를 명시
- 플랫폼 어댑터에서 키보드·IME·터치·클립보드 입력 검증

손글씨·도형·자유 배치 블록은 공통 데이터 표현과 플랫폼별 입력·표시를 분리한다. 압력·기울기·손바닥 방지 등 실제 동작은 지원 기기에서 검증한다.

## 3. 문법·표·변환 확장

### Markdown·HTML

Markdown 기본 문법을 먼저 검증하고 표·체크박스·각주 등 확장 문법을 단계적으로 추가한다. HTML 가져오기·내보내기는 허용 태그·속성과 URL 정책을 적용한다. 스타일·폰트·필기·고급 블록은 대상 형식에서 표현 가능한 범위만 변환한다.

입력 중 문법 변환, 리치 텍스트·소스 모드 연결, 코드 블록의 언어 선택·구문 강조는 편집 어댑터와 함께 검증한다. HTML 후보에는 문단·제목·목록·기본 서식·이미지·오디오·비디오가 포함되며, 허용 여부는 명시적인 정책과 표시 환경에 따라 정한다. 폰트 종류·크기·색상·배경색·정렬·들여쓰기·줄 간격은 공통 문서가 표현하는 범위와 각 출력 형식의 지원 범위를 구분한다.

### 나무위키 스타일 문법

전용 파서를 통해 제목, 서식, 링크, 인용, 각주, 접기 및 표 문법을 단계적으로 지원한다. 복합 문법·중첩·충돌 우선순위와 지원하지 않는 매크로의 처리 방식을 정의한다. 모든 문법과 표 속성의 완전 호환을 초기 전제로 두지 않는다.

기존 로드맵의 문법 후보는 여기서 관리한다.

- 제목: `= 제목 =`, `== 부제목 ==` 등 단계별 제목
- 텍스트 서식: `'''굵게'''`, `''기울임''`, `~~취소선~~`
- 링크: `[[링크]]`, `[[링크|표시텍스트]]`
- 인용·각주: `> 인용문`, `[* 각주내용]`
- 접기: `{{{#!folding 제목`으로 시작하는 접기 구문
- 표: `||셀1||셀2||`, `<rowspan=2>`, `<colspan=3>` 등 병합 속성
- 표 서식: `<bgcolor=#ff0000>`, `<color=blue>`, `<:>`, `<(>`, `<)>` 등 후보

표 내부의 목록·링크·이미지 등 중첩, 목차·앵커·문단별 편집, 표 템플릿을 검토한다. 문법별 실제 파싱 규칙과 출력 범위는 테스트 예제를 통해 확정한다.

### 표와 수식

기본 표·셀 병합·정렬·스타일을 먼저 검증하고, 행·열 조작과 범위 선택은 플랫폼별 UI에서 구현한다. 수식·셀 참조·SUM/AVERAGE/COUNT/MAX/MIN/IF 등 계산과 조건부 서식은 후속 확장 후보다. 계산 로직과 편집 UI·읽기 전용 표시는 분리한다.

- 행·열 삽입·삭제·이동, 크기 조절, 단일 셀·범위·행·열 선택
- Tab·Enter·방향키 탐색과 해당 플랫폼의 터치·펜 조작
- `=SUM(A1:A10)` 같은 수식, 절대·상대 셀 참조 및 의존 셀 변경에 따른 재계산
- 숫자·소수점·날짜·통화·백분율 표시 형식
- 값 기반 색상, 데이터 막대·색상 척도·아이콘 등 조건부 서식

### 데이터 보존

공통 문서·블록에 버전과 확장 데이터를 연결한다. 지원하지 않는 블록도 원본을 유지하며 대체 표시한다. Markdown·나무위키 문법·HTML 간 왕복 변환은 지원 범위에서 검증하고, 손실 가능 항목을 안내한다. 원본을 보존하는 경로와 단순 변환 출력은 구분한다.

## 4. 기술 검증 후보

TypeScript 기반의 프레임워크 독립적인 로직을 목표로 한다. ProseMirror 또는 이를 사용하는 편집 계층, 별도 파서, 협업 데이터 구조 등은 후보이며 구체적인 기반 기술은 검증 후 결정한다.

특히 후보 엔진의 DOM·입력·선택 의존성을 확인하여 공통 코어와 웹 편집 어댑터의 경계를 검증한다. 특정 엔진을 선택했다는 이유로 네이티브·서버·모든 플랫폼에서 동일하게 실행된다고 가정하지 않는다. 렌더러와 파서는 편집 UI 없이 사용할 수 있는 경로를 검증한다.

## 5. 협업 확장

협업용 변경 규약·CRDT 연결은 선택형 확장으로 검토한다. Yjs 등 후보를 사용하더라도 계정·권한, WebSocket 연결, 서버 운영, 재연결 및 기기 동기화는 호스트 서비스에서 담당한다. 기본 로컬 편집에 협업 서버를 요구하지 않는다.

사용자 존재감·커서 공유·댓글·공유 링크는 에디터 코어의 필수 기능이 아니라 앱·프레임워크의 후속 기능이다. 기능의 활성화 여부는 현재 호스트·실행 모드·권한에 따라 결정한다.

## 6. 렌더링·보안·확장

- HTML·스타일·URL은 공통 허용 정책을 정의하고 실제 정제 처리는 렌더링·가져오기 환경에 맞춰 연결한다.
- HTML 정제와 커뮤니티 코드 실행 격리는 별도 책임이다. 구체적인 정제 라이브러리와 격리 구현은 검증 후 선택한다.
- 테마 값과 서식 데이터는 공유할 수 있지만 CSS나 웹 UI가 네이티브 화면에 그대로 적용된다고 보장하지 않는다.
- 에디터 확장은 문서 스키마·명령·표시를 담당하고, 앱·사이트 확장은 메뉴·저장소·외부 서비스 등 호스트 기능을 담당한다.
- 공식·커뮤니티 플러그인의 플랫폼 태그와 테스트 영상은 [공통 검증 정책](../Framework/1.%20framework-runtime-and-plugin-policy.md)을 따른다.

## 7. 검증 관점

문서 파싱·직렬화·변경·데이터 보존을 검증하고, 대표 문서를 iPadOS·Android 앱 편집 환경과 웹 렌더러에서 확인한다. 입력·선택·IME·터치·펜·접근성·성능은 해당 환경에서 별도로 확인한다. 미구현 기능과 검증하지 않은 환경은 지원 완료로 표시하지 않는다.
