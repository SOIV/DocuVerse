# DocuVerse 앱 확장·AI·공유·협업

앱 호스트의 후속 기능을 정리한다. 초기 범위는 [앱 로드맵](05b_roadmap_and_future.md), 공통 확장 경계는 [프레임워크 구조](../Framework/02_architecture_and_extensions.md), 플랫폼 태그·테스트 영상·심사는 [공통 정책](../Framework/1.%20framework-runtime-and-plugin-policy.md)을 따른다.

## 1. 앱 확장 호스트

- 공통 에디터 확장은 문서 스키마·명령·변환·표시를, 앱 확장은 패널·메뉴·저장소·외부 서비스를 담당한다.
- 공식·커뮤니티 플러그인은 공통 공개 SDK를 사용한다. 공식 관리, 기본 탑재, 지원 플랫폼 및 실행 모드는 별도로 관리한다.
- 앱은 현재 플랫폼·호스트 버전·권한·필요 기능을 확인하여 지원하는 진입점만 실행한다. 호환 메타데이터만으로 권한을 허용하지 않는다.
- UI만 숨기는 방식으로 제한하지 않으며 해제 시 작업·타이머·구독·통신 등의 실행 수명을 정리한다.
- 공통 로직은 웹에서도 재사용할 수 있지만 웹 UI·빌드 플러그인이나 앱 전용 OS 기능까지 일괄 호환하지 않는다.
- 지원하지 않는 확장 블록은 원본을 보존하고 대체 표시한다. 플랫폼 변경·업데이트만으로 데이터를 삭제하지 않는다.
- 커뮤니티 코드의 권한·격리 방식은 기술 검증 후 확정한다.

업데이트는 해당 버전의 호환성·검증 상태를 확인하여 적용한다. 이전 버전의 호환 태그를 새 배포물에 자동으로 승계하지 않는다. 공개 전 영상 업로드·편집 허용·등록 거부 기준은 공통 정책에서 관리한다.

## 2. 테마·레이아웃 후보

기본 라이트·다크 테마와 설정을 우선 제공하고, 폰트·색상·사용자 테마 및 패널·탭 구성을 확장한다. 웹 CSS, 네이티브 UI 및 플랫폼 폰트는 어댑터에서 연결하고 동일한 구현을 요구하지 않는다.

작업 모드별 레이아웃, 드래그 재배치, 사용자 대시보드, 도킹 패널·그리드, 레이아웃 템플릿 공유는 후속 후보다. 다중 모니터·창 배치 등 데스크톱 특화 기능은 해당 앱 제공 결정 이후 검토한다.

## 3. 외부 API·자동화

외부에서 DocuVerse를 조작하는 공개 API와 앱에서 외부 서비스를 호출하는 커넥터를 구분한다. 공통 API 설계는 프레임워크 구조 문서를 기준으로 하며 앱은 네이티브 인증·비밀키 보관·네트워크 실행을 연결한다.

캘린더·메일·Git·지도·임베드 등 서비스별 연동은 선택형 공식 또는 커뮤니티 플러그인 후보다. 트리거·액션 자동화, 문서 변경·일정·태그·외부 이벤트 연동도 후속 기능으로 검토한다. 로컬 자동화와 네트워크·상시 서버가 필요한 자동화를 구분하고 플랫폼의 실행 제약을 검증한다.

사이트의 동적 ON/OFF는 프레임워크 운영 설정이다. 앱은 별도의 로컬 기능·온라인 서비스 활성화 상태를 가지며, 사이트 OFF 모드를 앱의 읽기 전용 전환으로 해석하지 않는다.

## 4. 다중 AI 제공자 연동

기존 문서에서 내부 약어로 사용한 `MCP(Multiple Chat Providers)`는 혼동을 피하기 위해 **다중 AI 제공자 연동**으로 정리한다. 별도의 외부 도구 프로토콜 지원은 이 기능과 분리하여 추후 결정한다.

- OpenAI·Anthropic·Google 등은 커넥터 후보이며, 실제 구현·검증한 제공자와 기능만 지원으로 표시한다.
- 사용자 API 키 또는 제공자가 허용하는 인증 방식은 호스트별로 연결한다. 키 등록만으로 모든 서비스·모델 기능이 작동한다고 가정하지 않는다.
- 공통 요청·응답과 제공자별 기능 차이를 구분하고 취소·오류·요청 제한을 처리한다.
- 문서·작업공간 컨텍스트와 전송 범위를 사용자가 선택할 수 있도록 설계한다.
- 온라인 AI 사용은 네트워크·인증·외부 서비스 조건에 종속된다. 로컬 편집에 필수로 요구하지 않는다.

글쓰기·요약·번역·교정, 태그·관련 문서 추천, 코드 설명·수정 제안, 사용자 프롬프트·워크플로우는 후보 기능이다. 구체적인 제공 범위와 사용량 정책은 별도 검증 후 결정한다.

문서 품질·가독성·감정 분석, 참고문헌·인용 생성, 작업 스타일에 따른 개인화와 규칙·AI를 조합한 자동화도 후속 후보로 둔다. 데이터 처리 범위와 제공자별 구현 가능성을 확인한 후 지원 범위를 정한다.

## 5. 공유와 권한

공유는 다음 경로를 구분한다.

| 경로 | 조건과 책임 |
| --- | --- |
| 파일 내보내기·전달 | 로컬에서 가능한 범위, 자동 동기화·협업과 별개 |
| 정적 사이트 게시 | 선택한 문서의 공개 결과 배포, 로그인·댓글·편집 서버 없이 가능 |
| 공식 클라우드 공유 | 업로드·계정·공유 권한·공식 서비스 플랜 적용 |
| 셀프호스팅 동적 공유 | 운영자가 구성한 인증·저장소·권한 적용 |

읽기·댓글·편집·관리 권한, 사용자·그룹 초대, 링크 만료·접근 제한을 동적 공유의 후보로 둔다. 공식 클라우드 업로드가 모든 종류의 게시·공유의 유일한 전제는 아니다. 정적 공개와 비공개 동적 접근 제어를 같은 기능으로 표시하지 않는다.

## 6. 실시간 협업과 팀 기능

CRDT 연결, 다른 사용자의 커서·선택·존재감, 변경 강조, 댓글·멘션·알림은 후속 온라인 기능이다. 공통 문서 변경 규약은 에디터 확장과 연결하고 통신·권한·저장·재연결은 호스트 서비스가 담당한다. 앱의 로컬 편집만 사용할 때는 해당 서버를 요구하지 않는다.

팀·역할·그룹 권한, 활동 로그·대시보드, 변경 검토·승인, 문서 구독은 후속 후보로 관리한다. 화상·음성 연결, 음성·영상 메모 공유는 필요성과 비용을 검토한다. 기기 간 백업·동기화·충돌 처리는 [저장·동기화 문서](05a_sync_and_performance.md)를 기준으로 한다.
